--- Version 1.1.1Beta2

This beta builds on 1.1.1Beta1; the changes are listed below.

- Regional/script language preferences now use one common engine (langutils), which includes the variants of
  1.1.1Beta1 (Thanks to Hugs11): English (UK / US / Australia / India / Canada), Spanish (Spain / Latin America),
  French (France / Canada / Belgium / Switzerland), Portuguese (Portugal / Brazil), Chinese (Simplified / Traditional),
  German (Switzerland / Austria) and Dutch (Belgium). The region is read from the track's language tag, its title
  or an external subtitle's file name; custom tags such as en-AU, es-419, zh-Hant work everywhere.
- All aliases and codes of the 1.1.1Beta1 variant table are recognised too (VFC, Canadienne, Latinoamericana,
  United States / United Kingdom, Chinese-character script labels, 3-letter regions such as fre-can / fra-fra).
- New: subtitle format preference (issue #30; settings, General): when several subtitles of the preferred language are available,
  the first format of your list (SRT, ASS/SSA, WebVTT, PGS, VobSub) that is present is taken. The format of embedded
  .mkv tracks is read from the file, that of external files from their extension, any other from a format word in the
  track title; when it is unknown nothing changes. The language always comes first.
- new: protection against a stale copy. The add-on no longer writes or uses compiled Python files (__pycache__; any left by an
  older version are deleted at start), its own modules are searched first, the log shows the version, folder and a code
  fingerprint it runs ("Running version ..."), and when another folder holds a copy of the add-on (an older version unzipped
  next to this one) an error is logged and a warning shown on screen: delete the old folder and restart Kodi.
  New button in the settings (General, Installation): "Check installation" shows a dialog, either "No stale versions
  detected and no second copy of the add-on is installed", or what is wrong (a second copy, leftover compiled files, or
  Kodi still running older code than the files installed: restart Kodi).
- Fixed: with a subtitle format preference set, a text track (ASS/SRT/WebVTT) that only has the forced/default flag (no "forced" in its name) is no longer excluded from non-forced rules, so the format preference can choose it (e.g. English ASS flagged forced+default with Japanese audio). Flagged image tracks (PGS/VobSub) and tracks named "forced" stay excluded; the unflagged track wins a tie within the same format; without a format preference nothing changes.
- Fixed: stored preferences: when the audio track is changed from the GUI and the conditional rules then switch the subtitles off (e.g. fre:non), the stored "enabled subtitles" kept the old value (true). The result of the rules is now stored as well.
- Fixed: the log no longer shows "Language setting AudioLang07 .. 12 has no valid value" at start (the settings have 6 audio preferences).
- Added: a track title with "Parisian", "Parisien" or "Parisienne" (e.g. French (Parisian)) is read as French from France (fr-FR).
- Changed: after LPM switches the audio at the start, the conditional subtitle rules are no longer evaluated a second time when the first evaluation already used the switched audio track (same result, one log block less).
- Sub converter: new group "Sub converter" in the General settings. The text color is now your choice (yellow, white, cyan, green, orange, pink, red, light blue, or any color typed as RRGGBB, or picked from a color chart with the button "Pick the color from a color chart..." (Kodi 21 and newer; an older Kodi shows the list of the preset colors); yellow stays the default; ASS/SSA subtitles keep their own styles).
- Sub converter: the audio languages it works for are your choice: up to 10 languages, or the new "Convert for audio in all languages" toggle. Japanese, Korean and Chinese stay the default, so nothing changes unless you change it.
- Sub converter: it no longer needs the regex filter or the conditional rules: it converts the selected subtitle whichever setting selected it (subtitle preferences, a stored preference, the file name, the regex filter, the conditional rules, or you). It also runs when only the sub converter is turned on. A subtitle you switch on, off or to another track during the playback is converted at once on Kodi 22 and newer, which announces such changes (Player.OnPropertyChanged): no polling needed there. Older Kodi still has the subtitle watcher, which now also runs for the sub converter (every 10 seconds; every 60 seconds as a safety net on Kodi 22).
- Fixed: sub converter: a subtitle you pick a few seconds after another one was converted was ignored (the add-on ignored every change for 5-8 seconds after a conversion, so it stayed unconverted). Now only the converter's own copy is ignored.
- Subtitle changes: the add-on reads the Kodi version (System.BuildVersion) and logs how it follows subtitle changes: announced by Kodi from version 22 (the watcher thread is then only a 60 second safety net), looked for by the watcher thread every 10 seconds on older Kodi. A change that happens just after a change made by the add-on is looked at when that is over, no longer dropped.
- Changed: the regex subtitle filter now respects the preferred subtitle language and format. Among the tracks the regex matches, it takes the language of the conditional rule for the playing audio (else the subtitle preferences), then the best format (the rule's 1st/2nd/3rd choice or the general order); the forced/default/original flags and "forced" names do not count there. If no matching track is in a preferred language, the filter works as before (ASS first, forced tracks deferred).
- New: every conditional subtitle rule (settings, Conditional Subtitle Preferences) has its own "Subtitle format for this rule" choice:
  the general order (default), or the 1st / 2nd / 3rd preferred format of the General settings put first for that rule only
  (the other formats follow in the general order; if the chosen format is not present the order still applies). In the custom
  rule field add -f1, -f2 or -f3 to the subtitle language, e.g. jpn:eng-f2 or jpn:eng-f3-ff.
- fix: sub converter: it now also runs when you switch subtitles by hand during the playback (to another ASS, WebVTT ... track of the
  video), not only at the start and after an audio change. A switch made while an earlier conversion is still running is
  converted as soon as that one ends; a copy already made for a track is reused.
- fix: sub converter: embedded SRT subtitles are converted as well (they were skipped): yellow, at the top; italic / bold / underline
  are kept, lines with a position or a non-bottom alignment tag keep their place.
- fix: subtitle format preference with external subtitle files. Two files of one language and name (Movie.en.ass and Movie.en.srt,
  Movie.en.ass and Movie.en.sup) could not be told apart, their format stayed unknown and an embedded PGS (.sup) track of the
  video won over a preferred ASS file. Kodi lists such files in the reverse of the folder's listing order; the tracks are now
  matched to the files that way. When that is not possible (files of several folders, or more files than tracks) a track ranks
  as the best format it may have, so a preferred text format is still taken before a PGS track.
- fix: regex subtitle filter / fallback and forced tracks. A forced track hit by the regex ("forced" is in the default
  pattern) no longer outranks a Signs&Songs track, and when only forced tracks match and conditional subtitles are on,
  the choice is left to the conditional rules (they pick a forced track when a rule asks for it). The final fallback
  (default / first valid subtitle) skips forced tracks, so a default-flagged forced track is no longer played just
  because it carries the default flag.
- fix: on the initial run the conditional subtitle rules are matched against the audio track LPM has just switched to,
  not the track Kodi started on (often the default-flagged one) while the switch is still pending.
- Language codes can be typed as 2-letter, 3-letter or BCP47 codes everywhere (custom preferences, Original audio list).
- New "Sub converter" for ASS/SSA and other text subtitles: lines are moved to the top, keeping styles and positions.
- Reworked seekback / "Fast Subtitles Display" ("Start & Resume" by default).
- Regex subtitle filter fixes (first match, no false "Signs & Songs" matches).
- The language of external subtitles is read from their file names; stored preferences save region and track title
  and can no longer be lost when saved at the same moment.
- Setting values of the 1.1.1Beta1 language variants (51-59) were renumbered: re-select regional languages in the settings.
- Settings strings of 1.1.1Beta1 (30351-30359) replaced by 30251-30267.

Details (newest first):
- new: "Select the audio track from the rules" (Conditional Subtitle Preferences, off by default): the first conditional rule whose audio language is available chooses the audio track, ahead of the audio preferences and the filename tag; only a stored per-video preference outranks it. The regex filter still chooses the subtitles first, then the conditional rules.

- new: filename preferences (setting "Try to set the audio and/or subtitle track from the filename") also read the languages written in the file name: 2 / 3 letter codes, regional and script tags and language names (Movie.JPN.UKR.subs.ENG.mkv, Movie.pt-BR.zh-Hant.mkv, [Japanese+Ukrainian]). Languages after "subs" are subtitle languages, the others audio languages. audiostream_N / subtitle_N still work and come first. When the name gives nothing usable, the first audio and the first subtitle track (number 0) are selected. Still the lowest priority: the regex filter, the conditional and normal preferences and stored preferences all outrank it. Only active with that setting on.

- fix: conditional audio rules "Undefined" / "Unknown" no longer take a track whose title names a language (an untagged track titled "Japanese" matches the Japanese rule), nor a tagged track that has "unknown" in its title.


- change: sub converter: an ASS/SSA subtitle is no longer turned into plain SRT. The copy is an .ass file with the track's own header (styles, fonts, colours) and every line's tags untouched; only lines at the bottom (alignment 1-3 from the style or an \an tag, with no \pos or one in the lower part of the picture) go to the top, a \pos line is mirrored. Signs, songs, effects and anything placed elsewhere stay where they are. Other text formats (WebVTT) still become yellow SRT at the top

- change: sub converter: the file is read in large sequential blocks (4 MB) instead of one small read per video/audio block, the way a demuxer such as ffmpeg reads it. Over http a 1.8 GB file went from tens of thousands of requests to a few hundred; locally the scan takes under a second on PC, nvidia shield based devices avg 5-90seconds dependening on filesize of playback, no interaction required will automatically work once rendered. 

- change: sub converter: tested with a video served over http and with an add-on (plugin://) item that resolves to an http address, also with '|' headers; the converted copy's name and the log no longer contain the headers, query string or user:password of the address
- note: it reads the file through Kodi's file layer, so nfs://, smb://, http(s):// and plugin streams that resolve to a Matroska (.mkv) file work; streams that are not a plain Matroska file (HLS, DASH, MP4) are logged as unreadable

- fix: sub converter: while it reads the video (the first time, a big file takes a minute or more) a subtitle change by the user was ignored by the watcher; now it is seen and stored as usual, and the converted copy is not selected over the user's choice
- change: sub converter: the log now says (INFO) when a conversion starts and why a video cannot be converted (not a readable Matroska file, e.g. a plugin stream)

- reworked sub converter to keep font & styling insteas pf converting to srt.
- change: sub converter: it now converts whenever the subtitle LPM selected is any text non picture based example :  SRT (ASS/SSA, WebVTT), with the same placement: lines that are positioned keep their place, the rest goes to the top, all in yellow
- note: PGS/SUP, VobSub and other picture subtitles are bitmaps; they cannot be turned into text without OCR, which Kodi add-ons do not have, so they are left as they are (the log says so)

- change: sub converter: it now works whenever the subtitle LPM selected is an ASS/SSA track, even if the video also has SRT, PGS or other subtitle tracks (before, every subtitle had to be ASS)
- change: sub converter: a line that the ASS file positions with a point (\pos / \move) is placed at that exact spot on the screen, moved from the script's resolution into the picture's place on the screen (also for films with black bars); lines with an alignment tag or a non-bottom style keep that alignment

- change: sub converter: only the lines the ASS file does not position itself (the usual bottom-centre dialogue) are moved to the top. A line that says where it goes, with an alignment tag, a \pos / \move, or a style that is not bottom centre (signs, top-style lines), keeps its place; every line stays yellow plain text

- new: "Sub converter" (shown with the regex subtitle filter or the conditional subtitles): with Japanese, Korean or Chinese audio and nothing but ASS/SSA subtitles in the video, the subtitle LPM selected is copied to a plain SRT (ASS styling removed, timings converted), shown at the top of the picture in yellow, and that copy is selected. It is made in the background from the Matroska (.mkv) file and kept in the add-on's own folder (converted_subs), which is emptied every time Kodi starts. Videos with any other subtitle format (SRT, PGS ...) are left alone

- change: the regex subtitle filter looks at every subtitle in track order and takes the first match (it says which tracks matched in the log); when several tracks match and some are ASS (the format with the styled signs & songs), the first ASS track is taken. The format is read from the video's header, for Matroska (.mkv) files; other containers keep the first match
- change: the regex exclusion pattern no longer removes a subtitle in which the filter matched a whole word: "Signs and Song Subtitles" or "Forced Subtitles" are kept, only a piece of a word ("titles" in "Subtitles") is still excluded

- fix: the regex subtitle filter took ordinary subtitles for Signs & Songs tracks: the "S&S" part of its pattern matched the "ss" inside a title, so a video whose subtitles included "Russian" (or "Swiss German", "Classic" ...) got that track before any conditional rule was tried. The two s of "S&S", "S + S", "S and S" or "S.S" now have to stand on their own. A stored pattern that still holds the old part is corrected when LPM starts

- change: "Fast Subtitles Display" is now "Start & Resume" by default: when LPM switches a subtitle on, a video in its first 10 seconds restarts from 0:00 and a resumed video jumps back 10 seconds, so the first lines show at once. A setting you chose yourself stays as it is

- change: "Fast Subtitles Display" is now "New Start only" by default (was "Disabled"): when LPM switches a subtitle on in the first 10 seconds, the video restarts from 0:00 so the first lines show at once. A setting you chose yourself stays as it is

- new: more regional variants in the language lists: English (India / Canada), German (Switzerland / Austria), French (Belgium / Switzerland), Dutch (Belgium); their region is also read from track titles ("Deutsch (Schweiz)", "Vlaams"). Other regions can be typed as custom preferences (de-CH, en_IN ...)
- new: LPM reads the subtitle file names in the video's folder (also the Subs / Subtitles / Sub / VobSub subfolders and Kodi's custom subtitle folder) and takes the language of each external subtitle from its file (pt-BR, en-AU, en-IN, zh-Hant, es-419, fr-CA ...), as Kodi misreads some of them (Movie.en-IN.srt as Indonesian); also for files named "Movie pt-BR.srt", "Movie_pt-BR.srt" or "Movie-pt-BR.srt". Streams it cannot map to a file are read from the name Kodi shows
- fix: stored preferences can no longer be lost when the "stored preferences" dialog and the service save at the same moment (the file is replaced in one step and keeps its permissions; a file being written is not read as empty; a file that cannot be read is never overwritten). When a delete in the dialog cannot be saved, the entry stays in the list and a message says so (was: removed from the list but still stored)
- fix: if playback stops during the start delay, LPM no longer applies the previous video's tracks
- fix: a language tag in a track title ("Portuguese (PT-BR)", "Spanish (ES-419)") gives the region, not the language part, and release words (eng-Full, en.HI, en.BD) are not taken as a region; zh-CHS / zh-CHT keep their script; "Mandarin" / "Cantonese" in a title no longer count as Simplified / Traditional
- fix: the Original audio list honours regions (pt-BR no longer takes an original track titled Portugal, en-AU prefers the Australian original track)
- fix: in the stored-preferences dialog, deleting a second entry removed the wrong one from the file
- fix: when LPM's own audio switch is already done at start, the conditional subtitles are re-checked without a second wait and seek
- fix: more external subtitle file names are read right: Movie.chs.srt / Movie.cht.srt as Chinese (Simplified / Traditional), Movie.pt.br.srt (region in lower case) as Portuguese (Brazil), and .text files are included; on Kodi 19 to 21 (3-letter codes) a plain and a regional file of one language (Movie.es.srt, Movie.es-ES.srt) are told apart; a subtitle never gets the language of another subtitle's file
- fix: custom conditional rules accept the -ff and -ss tags together in either order (en:en-ff-ss lost "forced" and read FF as a region); in the custom audio / subtitle preferences, where these tags have no meaning, they are ignored again, and a subtag that is no region or script (en-XX) is dropped instead of filtering out regional tracks
- note: the cause is in Kodi itself, which misreads external subtitle file names with a region tag (Movie.pt-BR.srt as Breton "br", Movie.en-AU.srt as "avt", Movie.en-IN.srt as Indonesian, Movie.fr-CA.srt as Catalan "ca", Movie.de-CH.srt as "ch"); LPM works around it. This is to be reported to the Kodi project, so that Kodi reads such tags (BCP 47) itself

- fix: when the subtitle Kodi had already selected matches the normal subtitle preferences, it now counts as a match: "Turn subtitles on" switches it on again (as in 1.0.x), and neither the file name tag nor the fallback replaces it
- fix: after LPM switched the audio track itself (audio, file name or stored preference), a user switching back to the track the video had started with is now always recognised as a change and stored
- fix: deleting a stored preference in the "stored preferences" dialog takes effect at once; before, the running service kept applying it until Kodi restarted, and its next save wrote the deleted preference back. An empty preferences file no longer stops the stored preferences from working
- fix: the "stored preferences" dialog (delete question, TV show / movie labels) and the "Log level" setting are now translated; French and Swedish translations completed
- new: regional language variants. The language lists have English (UK / US / Australia), Spanish (Spain / Latin America), French (Canada), Portuguese (Portugal) and Chinese (Simplified / Traditional); custom preferences accept tags such as en-AU, es-419, zh-Hant. The region of a track is read from its language tag or, as Kodi 22 drops it, from its title ("English (Australia)", "Brasileiro"). A regional preference takes a track of its region first, then one of unknown region, never one of another region; a plain preference (English, Portuguese) still takes the first track of its language
- fix: "Portuguese (Brazil)" now matches on Kodi 22, which reports Brazilian tracks as plain "pt"
- stored preferences also save the region and the title of the chosen tracks, so a stored Brazilian or Australian track is found again before another track of the same language
- fix: no more script error in the Kodi log when playback stops while LPM is checking an audio change
- fix: external subtitle files with a region in the name are recognised: Kodi reads Movie.pt-BR.srt as Breton and Movie.en-AU.srt as "avt"; LPM now takes the language from the name (pt-BR, en-AU, zh-Hant, es-419, fr-CA ...), so Portuguese, English and the regional preferences find them

First step towards BCP47: tags like pt-BR or zh-Hans are understood (region/script ignored, except Brazilian Portuguese)

- fix: a language code is no longer searched inside the track name ("en" matched "French", "it" matched "Subtitle"). The language tag wins; the track title is only read (whole words) when the stream has no language tag. An empty code can no longer match tracks with an empty language
- fix: regex subtitle filter keeps priority: a regex hit can no longer be overridden by the normal subtitle preferences, nor by conditional subtitles (also not after an audio change)
- change: tags in the file name ("Use filename": audiostream-N / subtitle-N) now have the LOWEST priority. The subtitle tag only applies when the regex filter and the normal and conditional subtitle preferences selected nothing; the audio tag only when the audio preferences selected nothing
- fix: 'Use filename' tags (audiostream-N / subtitle-N) were never recognised on Python 3.7+ (the tag split pattern split every character); now they work again
