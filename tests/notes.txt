Tests of Language Preference Manager
====================================

Quick start
-----------
    python3 tests/run_tests.py          menu (run all, one file, one class / test, tools on your own files)
    python3 tests/run_tests.py all      run everything and exit (exit code 0 = all passed)
    python3 tests/run_tests.py settings run one file (name without "test_": langcodes, selfcheck, ...)

Plain unittest works too, from the repository folder:
    python3 -B -m unittest discover -s tests -p "test_*.py"

Needs Python 3.8 or newer. Nothing else: Kodi is NOT needed, the tests replace the Kodi modules (xbmc, xbmcaddon,
xbmcvfs, xbmcgui, logger) by small fakes. Use -B (or PYTHONDONTWRITEBYTECODE=1) so no __pycache__ folders are
left in resources/lib: the add-on itself deletes compiled files at its start and warns about them.


The test files (no paths needed)
--------------------------------
test_langcodes.py             language codes, regions and variants (fr-FR, pt-BR, en-AU, zh-Hant), special codes
                              (Original, Any, Unknown, Undefined, None), a language named only in the track title,
                              languages written in a video file name
test_prefutils_integration.py preference evaluation with fake players: audio preferences and their order, subtitle
                              preferences, forced / default / signs tracks, keyword blacklists, the regex filter,
                              conditional rules (and audio chosen by the rules), "Original" audio and subtitles,
                              file-name preferences, subtitles stored after an audio change, the Parisian title
                              words, the second conditional run skipped after LPM's own audio switch
test_selfcheck.py             installation check: another copy of the add-on, compiled files, version and code
                              fingerprint
test_settings.py              settings.xml: language spinners complete, grouped and unique; every label defined in
                              English; translations (.po) consistent
test_kodirpc.py               the JSON-RPC calls for the streams (playing file, loading the converted subtitle, subtitles
                              on / off, info labels): answers, errors, garbage; the sub converter uses no Python player
                              methods for the streams; the playing check between file clusters is rate limited
test_subconvert_srt.py        sub converter: which codecs are convertible, SRT / ASS / WebVTT cues moved to the top
test_subconverter_options.py  sub converter options: text color (presets, typed RRGGBB, bad values, the color chart
                              button and its fallback list), up to 10 audio languages and the "all languages"
                              toggle, settings.xml entries, runs with any setting (not only with the regex filter
                              or the conditional rules); Kodi's subtitle notifications; the Kodi version decides
                              how subtitle changes are noticed: no watcher thread on Kodi 22+, on older Kodi the
                              thread only for stored preferences, never for the sub converter
test_subtitle_formats.py      subtitle format preference (SRT, ASS, WebVTT, PGS, VobSub): order, external files

All of them run without any file of yours.


Tools on your own files (menu items t1 .. t5, they ask for the paths)
--------------------------------------------------------------------
t1  Subtitle tracks of an .mkv video      asks: path of an .mkv
                                          shows the codec of every embedded subtitle track and whether the sub
                                          converter can convert it (text yes, PGS / VobSub no)
t2  Convert one subtitle track            asks: path of an .mkv, track number, language code for the file name,
                                          output folder (default: a folder in the system temp folder), text color
                                          (RRGGBB, default FFFF00)
                                          writes what the sub converter writes (colored text at the top, SRT; ASS
                                          stays ASS). Reads the whole file: slow on a network drive.
t3  Languages in a file name              asks: a file name or path
                                          shows the audio and subtitle languages the "use file name" setting reads
t4  Read a track title                    asks: the language tag Kodi reports, the track title, then preference
                                          codes to score it against (0 no match, 1 language, 2 language and region)
                                          e.g. fre + "French (Parisian)" scores 2 against fr-FR and 0 against fr-CA
t5  Check an add-on folder                asks: the add-on folder (default: this repository), and optionally the
                                          folder with your other add-ons to look for a second copy
                                          same check as Settings > General > Installation > Check installation, minus
                                          what the running service reports

Paths: typing or pasting a path is fine, quotes around it are removed, "~" works. An empty answer goes back to the
menu. Windows paths (D:\Videos\movie.mkv) and network paths that your operating system can open also work; the
tools read the file directly (they do not go through Kodi).


What these tests do not cover
-----------------------------
They do not start Kodi. The real behaviour inside Kodi (audio / subtitle switching by the service, the settings
screen, stored preferences of a library movie) has to be checked by playing a file with the add-on installed and
Debug logging on (add-on log level "Debug"). Useful lines in kodi.log:
    "Audio track changed from X to Y"       the user switched the audio
    "CondSubs : ..."                        which conditional rule matched
    "Subtitle track changed"                a user subtitle change was seen
    "Store user preference ..."             a preference was stored for the media
    "Sub converter: ..."                    the sub converter
